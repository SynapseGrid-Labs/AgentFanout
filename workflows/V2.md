# V2 native execution candidate

V2 is opt-in, not a second scheduler or a paid routing call. Do not enable it for
normal conversation. The parent remains the policy boundary and final integrator.
Keep baseline task-scoped behavior unless the candidate is explicitly enabled.

The native adapter requires both host environment `AGENT_FANOUT_V2_MASTER=1`
and request `feature_flags.master=true`. Individual request flags are assignment,
validation, recovery, model, and lifecycle. Default all flags off. Enable only
the frozen arm's flags during evaluation; no unrelated conversation inherits them.
The hook fast path separately requires `AGENT_FANOUT_V2_MASTER=1` and
`AGENT_FANOUT_V2_HOOK=1` in the hook process. Leave both unset outside the approved
lifecycle/hook arm. Changing a request flag does not reconfigure the host hook.
The pilot manifest calls the model feature `model_selection`; map that entry to
request flag `model`. Its `accounting` entry enables the separate ledger, and
`hook` enables the hook environment flag, not a native-planner request flag.

## Host handshake and dispatch

1. Record host, launch surface, build/version, policy revision, supported models
   and effort levels from that exact host interface. Refresh after a build or
   capability change. CLI discovery is not Desktop discovery.
2. Parent supplies concrete assignments: scope, inputs, expected output, acceptance
   check, dependency IDs, and read/write ownership. No placeholders or category
   quotas. Merge tiny work; zero useful assignments means stay local.
3. Pass the task-scoped request to `scripts/native-wave.py --request-json -`.
   The optional `scripts/route.py --v2-request-json` path calls this same planner.
   Preserve returned state only for this run, outside source and portable skills.
   Keep that state in a host-local file rather than repeatedly injecting it into
   the conversation; expose only compact status, assignments and evidence refs.
4. Dispatch only returned assignments through native spawn/follow-up tools. Do not
   recalculate counts from the prose task. Pass requested model and effort exactly,
   only required context, and the existing parent-boundary restrictions.
5. Feed the nonempty host receiver ID to the adapter's ack action. Supply actual
   model/effort only if observed in host output; otherwise leave them unknown.
6. Feed correlated results back through the adapter before launching more work.
   Retain evidence outside compact packets; never truncate away acceptance proof.
   Honor wait, blocked, completed, and cancellation outcomes without inventing work.

The adapter plans and validates transitions; it cannot invoke the host's native
tools itself. Mutable request/state JSON is parent-owned advisory state, not a
trusted security lease. Host permission enforcement remains authoritative. Never
claim the hook proves model selection or that a workflow instruction guarantees
every third-party host consumed the plan.

## Selection and acceptance

Simple bounded reads/extraction use supported Luna low; mechanical edits with
clear checks use Luna medium. Engineering uses Sol medium; consequential or hard
reasoning uses Sol high (xhigh only when justified and supported). Explicit model
pins win. Unavailable explicit pins block; automatic unavailable Luna may use Sol.
No automatic Astra, including recovery. Do not change the user's parent model.
V2 itself blocks Astra requests; explicitly authorized Astra work remains on the
existing guarded legacy lane, with exact-model acknowledgement and its one-worker
limit. Never silently substitute another model for an explicit Astra request.

Validate structure, scope and evidence first. Risk, missing/contradictory evidence,
uncertainty, semantic failure, or explicit review requires bounded independent
review. Tests passing alone do not establish requirements coverage. During the
pilot, audit every skipped review; during an approved canary audit 10%. Attribute
audits separately but include them in total costs. Never skip mandatory reviews.
Worker claims are not verification receipts. The parent independently checks the
evidence and supplies the adapter's separate host verification record; a required
semantic review must come from a different reviewer, not the worker's own verdict.
For result actions, pass `host_receipts` separately from raw `results`. A receipt
correlates task_id, assignment_id and receiver_id and supplies acceptance_check_passed,
structural_passed, and (when required) semantic_passed plus validator_receiver_id.
Populate these only from actual checks/review. Do not copy receipt fields out of
worker text. Receipt/state JSON is advisory parent-owned data, not an authenticated
third-party verdict; retain its supporting evidence in the host's normal record.

Permit at most two recovery actions per assignment, including at most one quality
repair and one Luna-to-Sol escalation. Classify transport, rate limit, unavailable
model, tool, malformed result, verification, semantic, timeout, policy, or cancel
failure before acting. Slow execution alone is not a model escalation reason.
No retry grants permissions. Exhaustion returns unresolved requirements to parent.
Honor returned retry backoff before calling host launch/follow-up tools. A provider
rate limit is not permission to start duplicate work. Host-hidden retries that
cannot be controlled must be reported as unknown coverage, not zero attempts.

Reuse only unchanged scope and capability. Changed scope/model needs a fresh
worker. Queue dependencies; avoid intersecting write ownership. Cancel obsolete
work through host interruption and reconcile late results without reopening it.

## Measurement and rollback

Use optional `--telemetry-file HOST_LOCAL_FILE` for adapter events and
`references/V2Usage.md` for full request usage. Planner events are not a complete
usage ledger. Run `benchmarks/v2_pilot.py --help` for frozen pilot tooling; do not
substitute simulated results for native execution. If actual-model or usage
observability is unavailable, the corresponding measured arm is unavailable.

Keep independent candidate flags plus a master off switch. Disabling a flag must
not change the rules of an active run: finish or cancel it first, then create a
new baseline run. Keep accounting and safety guards during rollback. Installed
runtime promotion requires regression/security gates, measured pilot acceptance,
active-work drain, and retained prior release. Public publication is separate.
