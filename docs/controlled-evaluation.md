# Controlled evaluation candidates

`evaluation_contracts.prepare_switch_window` validates a proposed U19 window from supplied observations. It performs no lifecycle operation. Normal admission must already be closed by the authorized coordinator owner, the selected domain must be independently fresh/certain/idle, and every identified prior job must have terminal effects, ownership, cancellation and accounting reconciliation. Running, queued, unknown or unrelated work blocks the candidate. The returned capability request still requires separate host authorization and the existing coordinator. Prior capability and serving epoch are retained for scoped restoration; broad kills and administrative off are not alternatives.

`compare_matched_samples` validates U20 serial/concurrent evidence with identical task-input multiset, exact model/profile/effort and validator identities, and matched warm/cold state. Routing changes require a separate experiment. It requires accepted-task/quality/repair counts, queue/load/elapsed observations, complete input/cache/reasoning/output accounting, numeric reservation charges, parent-context growth, separate resource-domain memory peaks and cancellation certainty. Missing provider dollars and quota remain unknown. Cache and reasoning are explicit subsets of normalized input/output; they must not be counted twice.

A submitted sample is not trusted live provenance. The returned arithmetic comparison labels `live_provenance_verified=false` and `savings_claim_authorized=false`; it does not claim cost savings, live conformance or successful execution. Independent provider/coordinator conformance, authorized measurements, evidence verification and human acceptance remain required. Offline fixtures validate the checks only.
