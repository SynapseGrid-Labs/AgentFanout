# Frozen V2 pilot

Status: **60 live model runs NOT RUN**. This harness prepares inputs and validates/imports evidence; it does not call providers or simulate model performance. Unit tests use explicitly synthetic usage and cannot produce promotion-eligible results.

`benchmarks/v2_pilot.json` freezes 12 self-contained tasks, starting file bytes, acceptance criteria and validator inventory: 2 trivial, 2 bounded, 3 engineering/debug, 2 parallel, 1 dependent/reuse, 2 high consequence. Its SHA256 binds every imported run. Any change creates a different pilot and requires rerunning all arms. The five cumulative arms are accounting baseline, assignment, validation/recovery, model selection, and lifecycle/hook, totaling 60 runs.

## Operator protocol

1. Run `python benchmarks/v2_pilot.py prepare NEW_DIRECTORY`. Each task/arm gets an isolated starting directory. Keep `private-plan.json` hidden from scorers. Execution order alternates forward/reverse across tasks to counterbalance ordering; do not reorder after observing results. Execute sequentially at the run level on the same host/runtime allocation, with each arm enabling only its listed features. Within-run delegation is allowed only by that arm.
2. Use actual host/provider execution tooling to run the supplied task prompt. Capture exact host, runtime revision, configuration, request IDs, requested and observed model IDs in raw evidence, all work/validation/recovery/hook traces and final files. Capture provider-reported usage and billing; unknown values remain JSON null. No unauthorized Astra use is permitted. Include cold start/setup, lifecycle and hook overhead and audit work in wall-clock latency and dollar totals; keep audit events separate. Record start/end UTC times. Tests and local review may have zero model usage only with evidence supporting zero, never by assumption.
3. Run `python benchmarks/v2_pilot.py check TASK_ID WORKSPACE` on an isolated execution host; this explicitly executes candidate code with the manifest's frozen standard-library assertions (60-second timeout per check, no sandbox supplied). Record each check result and its frozen check hash in `acceptance_results`; a failure blocks promotion. The high-path check requires symlink creation support. Run every listed validator or explicitly mark it skipped. Independently audit **every skipped validator**, record audit outcome/evidence and a dedicated `skipped_validator_audit` usage event. A failed audit fails the pilot. Use a different human or model scorer from the executor. Strip model/arm/host metadata from final task outputs, randomize review packet order, label only by blind ID, and score against frozen acceptance criteria before revealing arm mappings. Scoring cost is evaluation overhead shared consistently across arms; if run-specific, include it in validation usage. Blind IDs are pseudonyms, not cryptographic blinding; protect the mapping and metadata operationally.
4. Write one run JSON per execution and import with `python benchmarks/v2_pilot.py import-run RUN_JSON STORE EVIDENCE_ROOT`. Import verifies all referenced artifact bytes, rejects path escapes and refuses overwriting an existing run. Retain immutable artifacts outside the run working directory. A trusted operator must verify that traces actually demonstrate provider/model identity and accounting completeness; hashes alone cannot establish truth. Never relabel fixtures as measured.
5. Collect independent blind scores and run `python benchmarks/v2_pilot.py analyze STORE SCORES_JSON`. Save stdout as the review report using your host's normal artifact capture. All 60 unique runs/scores with one consistent provenance kind are mandatory. Synthetic analysis requires `--allow-test-fixtures` and is always labeled `TEST_FIXTURE_NOT_MEASURED`.

## Run import contract

Each run contains `run_id` (`task_id/arm`), `manifest_sha256`, `provenance`, `latency_seconds`, `duplicate_jobs`, `evidence`, `usage`, `validators`, `acceptance_results`, `reconciliation`. See `tests/test_v2_pilot.py:fixture` for an executable **synthetic schema example**, not measured data.

`latency_seconds` must match the timezone-aware execution window to within one millisecond. Measured model identities cannot be unknown/unavailable placeholders. The special `none` identity is restricted to system-role overhead with zero input/output tokens and supporting execution evidence.

All 60 measured runs must use the same provenance host and runtime_revision. Arms enabling model_selection also require a nonempty provenance capability_snapshot_id and capability_snapshot_evidence_sha256 referencing imported evidence from that host's capability handshake.

- `provenance`: kind (`measured` or `test_fixture`), host, runtime_revision, executor, started_at, finished_at (timezone-aware ISO timestamps). Measured runs also require `enabled_features` exactly matching the manifest arm. Raw evidence must additionally preserve observed model identity and arm configuration; requested model is not proof of observed model.
- `evidence`: nonempty list of `{path, sha256}` entries relative to EVIDENCE_ROOT. Include raw request/response metadata, terminal output, acceptance results and final artifact snapshot. Do not include credentials or confidential data.
- `usage`: nonempty list of events with event_id, host, provider, model (observed exact ID), request_id, phase, role, cost_basis, cost_usd, input_tokens, output_tokens, material_misroute (boolean), compensation_worker (boolean), retry_count (nonnegative integer). Worker/retry/compensation events also need worker_id. Roles are parent, worker, validator, retry, synthesis, audit, system. Request identity is the tuple (host, provider, request_id); repeated requests under different event IDs or across runs are rejected, and parent/synthesis must be disjoint per-request deltas. Cost basis is actual_charge OR api_equivalent_estimate and must remain identical across all 60 runs; they cannot be combined or compared. Measured events also require `model_observed: true` and `evidence_sha256` referencing an artifact proving that observation (for local non-model overhead use `model: none` with a unique local request identifier and execution evidence). Valid phases: execution, validation, recovery, skipped_validator_audit, overhead. Include all spawned/failed/retried work. Nullable numeric usage fields remain unknown, preventing promotion; absent usage is not free usage.
- `reconciliation`: complete=true, reviewer (independent of executor), inventory_evidence_sha256, host_requests (each has host, provider, request_id, role), zero_request_role_evidence (role to evidence SHA256 mapping). Exactly match usage to a terminal host export, including parent and synthesis. If either has no requests, an explicit evidence reference proving zero is mandatory. Inventory evidence must be a JSON export `{requests: [...], terminal: true, started_at: ..., finished_at: ...}` whose request list and window match the run; import validates its bytes and contents. The independent reviewer must verify the export covers the whole run and all spawned sessions, rather than constructing it from only the provided usage list.
- `acceptance_results`: one entry per frozen acceptance check with id, passed (boolean), check_sha256, evidence_sha256. All checks must be represented, their frozen code hashes must match, and any failure blocks promotion. Human review still evaluates narrative requirements not completely proved by finite assertions.
- `validators`: exactly the manifest's named validators, each status passed/failed/skipped. A skipped entry requires `audit: {result, evidence_sha256, usage_event_id}` referencing imported evidence and an audit-phase event.
- Scores JSON is a list of `{blind_id, blinded: true, scorer, quality, accepted, evidence_sha256}`. Quality is a preregistered fraction in [0,1]: fraction of acceptance clauses met; accepted requires all clauses and no unauthorized actions. Scorer must differ from executor; score evidence must be present in that run's evidence inventory.

## Gates and interpretation

Compare each cumulative arm to baseline with the median of the 12 paired per-task cost and latency ratios. Require at least 15% median cost improvement with latency at most 5% worse, OR at least 15% median latency improvement with cost at most 5% worse. Baseline zeros or unknown metrics cannot supply a ratio and block the economic gate. Require no per-task quality decrease and all acceptance checks passing (a conservative zero-tolerance definition of no material regression). Duplicate jobs, unauthorized Astra, failed validators/audits or unknown usage anywhere fail the pilot. The final cumulative arm must pass for promotion eligibility; intermediate-arm comparisons remain visible for attribution.

Report Luna material misroutes by task category in scheduled execution order. At two material misroutes, mark that category Luna-disabled; further Luna requests in the category fail the pilot. Usage events must be in actual chronological request order. Report distinct compensation workers per run/class and summed request retry counts, including their costs through the same usage ledger. A material misroute means an incorrect assignment/model decision requiring materially corrective work, adjudicated independently from the routing outcome evidence.

This is a small directional pilot, not a statistical significance claim. It has one observation per task/arm and cannot measure variance reliably. Independent evidence review is still required before accepting promotion eligibility; schema validation cannot prove authentic provider telemetry, actual blinding, exhaustive billing, execution order, or absence of undisclosed duplicate work. Host/runtime feasibility must be established separately before spending on the 60 live evaluations.
