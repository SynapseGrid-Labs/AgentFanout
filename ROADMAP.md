# Roadmap

AgentFanout now leads with a compact task-scoped skill and Codex plugin that
checks a tokenized post-batch decision on intercepted native-worker events. The earlier
Linux/POSIX runtime remains an optional strict profile with atomic CLI,
project/session binding, admitted Grok direct-HTTPS and attested Local
bounded-file lanes, and cross-harness contracts. This is a bounded product, not
a universal enforcement claim about arbitrary third-party harnesses.

## Near Term

- Keep GrokCLI subscription, coordinator Local and mixed upgrade controls off
  until their distinct installed identity, boundary, resource, usage, egress and
  live conformance gates pass. Conditional installed Grok wire mapping and
  deferred work are listed in [candidate status](docs/candidate-status.md).

- Complete recorded user UAT for the immutable `0.4.0-rc.1` candidate before
  considering any public publication.
- Run Codex plugin discovery/install and repeated-wave UAT on each declared
  minimum Codex version and supported operating system.
- Add a tool-capable Local worker sandbox adapter. The current Local lane is a
  credential-free no-tool data client with signed capability/bridge evidence.
- Add a separately trusted real-provider attestation mechanism before admitting
  native Codex workers.
- Add cross-provider validator escalation without making it the default cost.
- Add an active, signed external-harness challenge/capture protocol; the current
  checker remains a structural linter.
- Add cgroup/container or equivalent supervision for descendants that detach
  from the launched POSIX process group.
- Add a sandboxed workspace/repository-tool adapter; keep generic work blocked
  until it passes input-mode, tool, cancellation, and effect conformance.
- Add measured price-table injection and savings reports without publishing
  guessed provider prices.
- Feed reviewed outcome calibration into route eligibility. Launch discovery
  remains readiness evidence, not task-quality evidence.
- Add clean-room macOS/Windows coverage for the plugin; keep the optional
  strict runtime's Linux/POSIX boundary explicit.

## Adapter expansion

New host adapters must add:

- a `HostCapabilityManifestV1` and conformance fixtures
- provider probes
- endpoint and key validation
- provider-native worker timeouts and cancellation
- queue supervision
- provider-specific probes that produce host capability attestations
- optional local raw-result artifacts referenced by compact packets

An adapter is optional. An enforcement boundary is not optional for any run
described as enforced.

## Not Planned For Core Skill

- Built-in access to private account tools.
- Worker ownership of secrets or credentials.
- Worker ownership of git state or destructive actions.
- Final synthesis outside the main session.
